# convex-rate-limiter-demo Update Design

**Date:** 2026-04-02
**Scope:** Update the demo app to use `convex-rate-limiter@0.1.8` and demonstrate all three public APIs.

---

## Goal

Upgrade the demo from v0.1.6 to v0.1.8 and add complete coverage of all three component functions: `checkRateLimit`, `enforceRateLimit`, and `peek`.

---

## Architecture

No new tables or services. The demo is a Next.js app that calls Convex actions/queries, which in turn call into the `convex-rate-limiter` component. The only changes are:

1. Package version bump
2. API path correction (`.convex.` segment removed in v0.1.8)
3. A new backend action for `enforceRateLimit`
4. UI expanded to three cards + updated code snippet

---

## Backend Changes (`convex/`)

### `package.json`
- Change `"convex-rate-limiter": "^0.1.6"` → `"^0.1.8"`
- Run `npm install` to pull the new version

### `convex/actions.ts`
Three exported actions:

| Action | Component function | Rate config | Returns |
|---|---|---|---|
| `loginAttempt` | `checkRateLimit` | 5 req / 1 min | `{ allowed, remaining, resetAt }` |
| `enforceAttempt` | `enforceRateLimit` | 3 req / 1 min | `{ remaining, resetAt }` or throws `ConvexError` |
| `getStatus` | `peek` | mirrors login (5 / 1m) | `{ remaining, resetAt \| null }` |

All paths updated from `components.rateLimiter.convex.rateLimits.*` → `components.rateLimiter.rateLimits.*`.

`enforceAttempt` catches `ConvexError` with `data.code === "RATE_LIMITED"` and returns a structured error object `{ rateLimited: true, resetAt }` so the UI can display it cleanly (actions can't propagate ConvexError to the client directly in all cases).

### `convex/_generated/`
Regenerated by running `npx convex dev` after the package update. New component paths will not include `.convex.`.

---

## UI Changes (`app/page.tsx`)

### Layout
Three-column grid (collapses to 1 col on small screens). Each card is self-contained with its own state.

### Card 1 — `checkRateLimit`
- **Title:** Check Rate Limit
- **Scenario:** Login protection — 5 requests / 1 minute
- **Button:** "Send Login Request"
- **Shows:** Progress bar (remaining/limit, color-coded green→amber→red), status badge (✓ allowed / ✗ denied), reset countdown

### Card 2 — `enforceRateLimit`
- **Title:** Enforce Rate Limit
- **Scenario:** Strict action guard — 3 requests / 1 minute
- **Button:** "Send Guarded Request"
- **Shows:** Same progress bar. When limit is exceeded, displays the ConvexError payload (`code: "RATE_LIMITED"`, reset time) to demonstrate the throw behavior explicitly

### Card 3 — `peek`
- **Title:** Peek Status
- **Scenario:** Read-only quota check — mirrors login (5 / 1 min)
- **Button:** "Refresh Status"
- **Shows:** Current remaining slots and resetAt without consuming a slot. No progress bar decrease on click — this visually proves peek has zero side effects

### "How it works" code block
Updated to show all three APIs with the corrected (no `.convex.`) path:
```ts
// checkRateLimit
components.rateLimiter.rateLimits.checkRateLimit
// enforceRateLimit
components.rateLimiter.rateLimits.enforceRateLimit
// peek
components.rateLimiter.rateLimits.peek
```

---

## Error Handling

- `checkRateLimit`: `allowed: false` is a normal response, not an error — card shows denied state
- `enforceRateLimit`: throws `ConvexError({ code: "RATE_LIMITED", remaining: 0, resetAt })` — action wraps and returns `{ rateLimited: true, resetAt }` to the UI
- `peek`: never throws for business reasons — only network/runtime errors possible

---

## Testing Criteria

- Card 1: clicking 5 times within a minute shows the counter drain to 0 and then displays denied state
- Card 2: clicking 3 times shows the ConvexError payload on the 4th click
- Card 3: clicking "Refresh" after using Card 1 shows the same quota drain without consuming additional slots
- "How it works" snippet shows correct paths and all 3 APIs
